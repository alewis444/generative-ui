ADJUST — NEGOTIATED COMPOSITION
How it works

Here you can talk back, and the model edits the existing composition instead of starting over. You can swap a component's type ("swap the checklist for a stat bar"), add one ("add a card for the caterer," within the 3–6 limit), remove one, or edit a component's data in place ("give the budget a $50 buffer"). Added or changed components get marked; anything unmentioned stays as it was.

USE CASE — THREE WAYS IN

Three entry points, because they're three different jobs.

"Show me something already built," "I know exactly what I want," and "help me figure out what I want" are three different asks. One box trying to serve all three tends to serve none of them well — this splits them at the door, and only brings them back together once something has actually converged (a picked dashboard or a picked angle).

Not a fourth difficulty tier. Shape, Atomic, and Adjust are a real ladder where each one is strictly harder to build and contains the last. This isn't harder than any of them; it's a decision about which entry pattern a person meets first. Ask AI just calls the Atomic mechanic directly; both Dashboard and Plan Together hand off into Adjust's negotiation state once something concrete exists to refine.

IRRESPONSIBLE — NO CLOSED SET, NO RULES

What happens when nothing is fixed.

Shape picks from 5 screens. Atomic composes from 6 components. Adjust edits under standing rules that always win. This is what's left once you remove all three — the model free-styling a UI for the same brief, with no shared vocabulary and no memory of the last answer.

Attempt 1 of 4

Most real AI coding tools live closer to this tab than to Adjust. Even with an existing convention in the codebase, it's a strong pull toward consistency, not a hard wall — if the project uses MUI but the task calls for something MUI doesn't have, the tool will often just install a purpose-built package for that one piece rather than refuse. There's no rule saying the library is fixed and always wins over the request, even when the request implies something outside it. It can always reach outside. That gap is why this project matters: without a design system enforced as an actual constraint, not just a convention, "AI-generated UI" quietly comes to mean whatever the model felt like assembling this time — and that's the definition worth arguing with.

SCALE — GROWING THE CLOSED SET

Six components today. Six hundred someday. Same rule.

A demo needs six components to make the point. A real product's design system might register sixty, or six hundred, across a dozen teams. The number changes. What can't change is the rule Adjust already showed: the model composes only from what's registered, and never reaches outside it — no matter how large "registered" gets.

6 components → 60 components → 600 components → same rule, every time
What happens when a request doesn't fit
Reaching outside
  • Bend an existing component to do a job it wasn't designed for
  • Pull in a new library or one-off component for a single screen
  • Let the model invent something plausible-looking that isn't registered anywhere
The set stops being closed. Every future request can now justify its own exception.
Designing around it
  • Compose the nearest fit from what's already registered
  • Flag the gap for the people who own the system, instead of papering over it
  • A new component gets designed, reviewed, and registered deliberately — then, and only then, the model can use it
The set grows. It never gets punctured.

This is why Irresponsible and Scale are opposite failure modes of the same problem: one has no system to violate, the other has a system large enough that violating it starts to feel harmless. The discipline is identical at 6 components and at 600.
